BlockSocial — design system, component library, and the Android block screen

The brief forbids designing the whole app in one request, so this pass covers the token system and the signature surface only. Everything below is Android; iOS is a separate design and a separate pass.

Assumptions I made
  • No existing design system, so tokens are designed here from scratch (§12).
  • Dark theme is authored first — night scrolling is the core scenario (§13).
  • Copy is written as real product copy, not lorem, but every string is a placeholder for localization (§16).
  • Bypass grant shown as five minutes wall-clock, the Android baseline (§7).
Direction, and why
  • Cool graphite surfaces with one desaturated teal accent: calm, low chroma, comfortable at 1 a.m.
  • Danger red exists as a token but appears on exactly one screen — delete all data.
  • Every state carries a shape or a word as well as a hue, never hue alone (§11, §15).
  • Manrope for interface, IBM Plex Mono for times, counts and metadata — measured values read as measurements.
Not designed, on purpose
  • No account, sync, paywall, ad slot or coach surface (§4).
  • No countdown gate on the primary action, no nagging repeat pattern (§7).
  • No shared Android/iOS block mockup (§5).
  • No connectivity state anywhere — offline is normal (§9).

Heights 56 / 52 / 50 dp — all above the 48 dp minimum, primary always the tallest. Disabled is a surface step plus lowered on-surface, never opacity on the whole button, so the label keeps 4.5:1. A bypass row is the same size, same type, same position as a stayed row — only the leading glyph differs, square versus ring (§6.6). No red, no strikethrough, no dimming. Every row states why the rule was active, so history is auditable. Empty state uses the same glyphs in dashed form, so the legend is learned before there is data.

Four fixed slots — enables / is read / is never read / how to revoke — in that order for every permission, which is what makes prominent disclosure defensible on Android (§6.2). Squares for what happens, rings for what does not, so the pairs are distinguishable without hue. The card looks nothing like a system sheet: product type, product corners, and a line saying the next screen belongs to Android. Denial keeps a forward path and never implies the app is broken.

2hEmpty-state block, loading, and the offline non-rule
No rules yet
A rule decides when a pause appears. Most people start with one weekday evening.
Loading · skeleton, only where a real delay exists
no shimmer loop — §14 forbids attention-grabbing motion
Everything is on this device. BlockSocial has no account and no server, so there is no offline state and no connection warning anywhere in the app.
Error, with a cause and a way out. A rule could not be saved because its start and end times are the same.

Empty states propose one action, phrased as what most people do, never as a nag. Skeletons are static — no shimmer, no pulse (§14) — and appear only where a real delay is possible; local reads are instant and get none. Offline is documented as a non-state so nobody adds a connection banner later (§9).

Reads in one fixation. App name, rule, end time, two targets — nothing else competes. Targets 60 dp primary / 56 dp secondary, both full width. Focus order title → primary → secondary → footnote, so a screen-reader user reaches the way out first. Footnote is a count, never a rate or a streak, and never phrased as progress.

The metaphor is structural, not illustrated: the centre band is physically held between two rules with empty space above and below — a threshold, not an alarm. The 3 dp column is elapsed-vs-remaining in the rule window; it is decorative reinforcement, and the same fact is stated in words beside it. Shape codes the choice — filled square for staying, hollow ring for opening — matching history rows. Provisional: depends on overlay stability, spike A-02; the fallback is 1b, which needs no band.

Context without scoring. Six opens are shown as six marks — squares for stayed, rings for opened — so the record is legible without hue and carries no bar, percentage or trend line. “2 opened” is not styled as a loss: same size, same row, neutral outline. No streak here — streaks live on the dashboard, per §11, so the block screen never applies loss pressure. Risk to test: this is the densest option and the one most likely to break the three-second rule.

1fStress test of 1c — largest font scale and Russian
icoInstagram
Дверь придерживает правило
Вечера по будням — пн–пт, 22:00–07:00. Осталось 6 ч 12 мин.
ничего не заблокировано навсегда

What breaks and how it is fixed. The held panel keeps flex:0 0 auto and sizes to its content; the two outer regions take flex:1 / min-height:0, so the empty space above and below is what shrinks — the band is the last thing to yield, exactly as in 1c. Buttons switch from fixed height to min-height and wrap to two lines rather than truncate. The closing line drops its second sentence at this scale; it is reinforcement, not information. Russian runs ~30% longer and still fits without ellipsis.
